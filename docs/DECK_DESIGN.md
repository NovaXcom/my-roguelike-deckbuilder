# デッキ化 設計書（2人別デッキ × 作戦予約）

状態: **設計（未実装）**。実装は D0〜D6 の段階に分け、各段階で `npm test` と Bot バランス確認を通す。
関連: `GAME_DESIGN.md`（§3「毎ターンランダムに引き直すのではなく…」を本書で改める）、`src/core/battle.ts`、`src/core/plan.ts`

## 0. 目的と原則

「Slay the Spire は *どんなデッキを作るか*、このゲームは *2人でどんな1ターンを作るか*」。
すでに入っている **行動ポイント(AP)＋作戦予約＋ブレイク/チェイン/属性反応＋複数編成** を壊さず、その上に「デッキを育てる」軸を足す。

守る原則:
1. **順序のパズルが主役**。ランダム性は「手札が毎回違う」程度に留め、運ゲーにしない。
2. **ルールを増やしすぎない**。CDと疲労のような二重の制約は作らない（§4）。
3. **UIは今の形を維持**。スキルボタン＝手札のカード。作戦パネル・予想表示はそのまま使う。
4. コアロジックはUI非依存でVitestテスト。Botで踏破率を確認（目標 35〜50%）。

## 1. 現状 → デッキ化の対応

| 今 | デッキ化後 |
|---|---|
| キャラごとのスキル一覧(常に全部使える) | キャラごとのデッキ。手札のカードだけ使える |
| スキル = `SkillDef` | カード = `CardDef`（`SkillDef` を拡張。効果計算は流用） |
| クールダウン(CD) | **疲労**（§4）。強いカードが一定ターン手札に戻らない |
| 待機（常に押せる行動） | **待機カード**（デッキに入る。毎回は引けない） |
| 装備の固有スキル | 装備中、そのカードがデッキに加わる（外すと抜ける） |
| スキルポイントでLv強化(倍率) | カード強化（分岐あり）。報酬/休憩所で選ぶ |
| 戦闘報酬: 装備＋SP | 装備に加えて **カード報酬3択** |
| 超音波(CDを封印) | **カード封印**（手札1枚を2ターン使用不可） |

## 2. データモデル

```ts
// カード定義(静的)。SkillDef をそのまま包む形で、効果計算(previewSkill/strike)は無改造で使う
interface CardDef extends SkillDef {
  owner: Role | 'link';          // ナイト用 / エレメンタリスト用 / 連携(共通)
  rarity: 'basic' | 'common' | 'rare' | 'legendary';
  fatigue?: number;              // 使用後に疲労する(手札に戻らない)ターン数。無ければ捨て札へ
  exhaust?: boolean;             // 使い切り(その戦闘中は戻らない)
  upgrades?: CardUpgrade[];      // 強化の分岐(§7)
}

// カード実体(動的)。同名カードを複数持てる
interface CardInst { uid: number; defId: string; level: number; branch?: string; sealed?: number }

// 戦闘中の山札(キャラごと)
interface DeckState {
  draw: CardInst[]; hand: CardInst[]; discard: CardInst[];
  fatigued: { card: CardInst; turns: number }[];   // 疲労ゾーン
  exhausted: CardInst[];
}
// ラン中の恒久デッキ: RunMember.deck: CardInst[]
```

- `MemberState.skills/cooldowns/levels/used` を `deck: DeckState` に置き換える。`used`（同じカードは1ターン1回）は不要になる（手札の実体を使い切る）。
- 乱数は戦闘用シード `Rng` を `BattleState` に持たせ、決定論的にする（テスト・リプレイ・バグ再現のため）。

## 3. ターンの流れ

```
プレイヤーターン開始
  1. 疲労ゾーンのカードの残りターンを-1。0になったら捨て札へ
  2. 各キャラが手札上限(4)まで引く。山札が尽きたら捨て札をシャッフルして山札に
  3. 連携カードを1枚引く(§6)
  4. APが3に回復
作戦を組む（今と同じ。手札のカードを最大3手まで予約）
実行 → 順に処理
  - 使ったカード: 疲労あり→疲労ゾーン / 使い切り→除外 / それ以外→捨て札
敵のターン（今と同じ）
ターン終了: 未使用の手札は **持ち越す**（捨てない）
```

決定事項（推奨）:
- **手札は持ち越し**。理由: 次ターンの作戦を見越して「今は出さない」判断ができ、順序パズルが深くなる。毎ターン全捨てにすると、引き運の影響が大きくなりパズルが崩れる。
- **手札上限は1人4枚**（2人で8枚、APは3）。毎ターン約3枚使い、3枚引くのでほぼ一定。
- 手札が減る要因は「疲労・使い切り・封印」。これが戦術変化の源（§5）。

## 4. 疲労（CDを置き換える）

「CD」と「疲労」は同じ“強いカードを毎ターン使えない”ための仕組みなので**併用しない**。CDを廃止し、疲労に統一する。

| | CD(今) | 疲労(提案) |
|---|---|---|
| 強カードを使った後 | スキル欄に残り、数ターン灰色 | **手札から消え**、数ターン後に捨て札へ戻る（再び引かれるまで使えない） |
| 戦術への影響 | 使えない期間が固定 | 戻った後も山札を回すまで来ない → デッキ構成が影響 |
| 例 | シールドバッシュ CD2 | シールドバッシュ 疲労2（2ターン後に捨て札→再シャッフルで復帰） |

これで「強攻撃を使うと、次のターンは防御・魔法・連携・待機が中心になる」（提案の§13）が自然に起きる。
基本スキルの疲労: 斬撃0、バッシュ2、挑発3、守護2、ファイアボルト0、アイスランス1、サンダー2、ヒール3（＝現在のCD値をそのまま移す）。
→ **既存の数値バランスをほぼ保てる**のが利点。

## 5. 初期デッキ

目標: 1人10枚前後。「基本カード」中心で、報酬で個性を足す。

**ナイト（10枚）**: 斬撃×3、シールドバッシュ×2、挑発の構え×1、守護の盾×2、**防御**×1(新: ガード6。AP1)、**待機**×1
**エレメンタリスト（10枚）**: ファイアボルト×3、アイスランス×3、サンダーボルト×1、ヒール×1、**魔力集中**×1(新: 次の魔法×1.3・AP1)、**待機**×1

シミュレーション（手札4枚、20万回の試行）:
- 「ナイトが攻撃カードを1枚も持たない」: 約2.4%、「エレメンタリストが攻撃魔法ゼロ」: 0%
- 「バッシュ（ブレイク源）＋攻撃魔法が同時に手札にある」(基本チェイン成立): **約67%**（手札5枚なら約78%）
- 「大きなブレイク源（バッシュ/サンダー）がどちらにも無い」: 約20%

→ 引き運で詰まる確率は低いが、「ブレイク源が無い手札」は5回に1回。**緩和策**（§9）を入れる。

## 6. 連携カード（2人共通）

- ランごとに共通の「連携デッキ」(最初は3〜4枚)を持ち、**毎ターン1枚引く**（手札上限2）。AP消費は0〜2。
- 連携カードは「作戦の前の手を参照する」ので、順序パズルとの相性が最も良い。実装は `plan.ts` の逐次処理で `lastDamage`/`lastElement` を状態に持てば足りる。

| カード | AP | 効果 |
|---|---|---|
| 追撃 | 1 | 直前の攻撃と同じ対象に、その50%の追加ダメージ |
| 魔力付与 | 1 | 次のナイトの物理攻撃に、直前の魔法の属性を付与（反応の起点になる） |
| 属性変換 | 0 | 敵の最後の属性を、好きな属性に書き換える（反応を狙って起こせる） |
| 反撃指令 | 1 | このターン、敵の攻撃を受けたナイトが反撃（ガード量に比例） |
| 魔法障壁 | 2 | 味方全員にガード10。次の強攻撃の予告ターンに有効 |

## 7. 強化と分岐（スキルLv → カード強化）

- 現在の「Lv1→2→3の倍率」は廃止し、**カード強化**に置き換える（スキルポイントの代わりに、休憩所/報酬で強化を選ぶ）。
- 強化は2段階。Lv2は数値強化（現行の×1.2相当）、**Lv3は分岐**(2択)。

例（ファイアボルト）:
- Lv2: 威力 7→8
- Lv3-A 燃焼型: 火傷を付与（4×3）
- Lv3-B 連鎖型: 次に使う雷カードの反応ダメージ+50%

## 8. 装備との関係

- 武器の固有スキル → **固有カードがデッキに加わる**（装備中のみ）。
- 固有効果 → **カードを書き換える**。例: 砕きの腕輪=「シールドバッシュ」が「砕撃」に変化（ブレイク時に出血）、炎の魔導書=「ファイアボルト」が「燃焼付与＋次の雷強化」になる、守護の剣=「守護の盾」が「次の攻撃のダメージ軽減」付きになる。
- 実装: `CardDef.variants: { requires: EquipEffectId; replaces: string }`。戦闘開始時にデッキ構築で置換。

## 9. ランダム性の緩和（パズル性を守る）

1. **開幕手札の保証**: 1ターン目の手札に、各キャラの「攻撃カード1枚以上」と「ブレイク源1枚以上(合計)」を必ず含める（山札の並びをシード内で調整）。
2. **山札の中身を見られる**: 山札/捨て札/疲労ゾーンの一覧を確認できる（引いていないカードは「何が入っているか」は分かる）。
3. **次に引くカードを1枚予告**（山札の一番上を公開）。作戦に「温存」の判断材料ができる。
4. **ブレイク温存は選べる**: 敵の予告が通常攻撃なら温存→待機、強攻撃ならブレイク（既存の仕組みを継続）。
5. **手札持ち越し**（§3）。

## 10. 報酬・店・休憩所

| 場面 | 提供 |
|---|---|
| 通常戦闘 | 装備(確率) ＋ **カード3択（スキップ可。スキップ時+ゴールド）** |
| エリート | 装備(確定Rare+) ＋ カード3択(Rare以上) ＋ 強化1回 |
| ボス | Legendary装備 ＋ カード3択(Legendary含む) |
| 休憩所 | 回復 / **カード強化1回** / **カード削除1枚** から選択（今の「修練」に置換） |
| ショップ | 装備 ＋ カード販売3枚 ＋ **カード削除(値段は回数で上がる)** |
| 呪われた宝箱 | 強い装備/カードの代わりに最大HP-10%（今のまま） |

- **カード削除**を重要な戦略にする。デッキ10→8に薄くすると、強化済みカードを引く確率が上がる。
- 融合（2枚→1枚: 例 斬撃＋バッシュ→砕撃）は D5 で検討。

## 11. 敵・ボスとの関係

- 敵の予告・複数編成・守護・奮起・封印は**そのまま**。「封印」は「手札のカード1枚を2ターン使用不可」に変更。
- 超音波の標的選択: 手札の中でレアリティ/疲労が最大のカード。
- ボスは多段階（Phase2 激昂/Phase3 灼熱）にして、**「ビルド検査」**にする（D6 以降、デッキ化が安定してから）。

## 12. UI

- 画面下のスキルボタン＝手札（キャラ別に左右）。枚数が変わるので、ボタン幅は枚数で分割（今も実装済み）。
- 追加表示: 山札/捨て札/疲労の枚数（各キャラのヘッダー）、クリックで一覧。
- 手札の引き・捨てにカードのスライド演出(Juice)。使用カードは作戦パネルへ飛ぶ。
- 連携カードは画面中央（作戦パネルの下）に1〜2枚。
- スマホ: 手札8枚＋連携2枚＝10枚になり、タップ領域が窮屈になる。**手札上限を3に下げる／手札を横スクロール**のどちらかで要確認（D1 の実機検証項目）。

### テスト計画（UI非依存）
- 山札: 引く枚数、シャッフル(シード固定)、山札切れ→捨て札再生成、手札上限、持ち越し。
- 疲労: 使用→疲労ゾーン→指定ターン後に捨て札へ。使い切りは戻らない。
- 作戦: 手札に無いカードは予約できない。同名カードは手札の枚数ぶん予約できる。
- 開幕手札の保証が全シードで成立する。
- 装備によるカード置換、削除/強化後の戦闘反映、封印、連携カードの順序依存。

## 14. 決めたいこと（推奨付き）

| # | 論点 | 推奨 | 理由 |
|---|---|---|---|
| 1 | 手札の扱い | **持ち越し** | 順序パズルが深くなり、引き運の影響が小さい |
| 2 | CDの扱い | **廃止し疲労に統一** | 二重制約は複雑。数値は現行CDを移植すれば保てる |
| 3 | 手札上限 | **4（PC）/ スマホは実機で確認** | チェイン成立率約67%、窮屈さはD1で検証 |
| 4 | 連携デッキ | **共通1デッキ、毎ターン1枚引く** | 「2人でどんな1ターンを作るか」の核になる |
| 5 | スキルポイント | **廃止（カード強化に統合）** | 報酬体系を1本化 |
| 6 | 乱数 | **戦闘シード付き＋開幕手札保証＋次の1枚予告** | 運ゲー化を防ぐ |

## 15. リスクと対策

- **複雑さ**: 「敵シールド＋ガード＋ブレイク＋反応＋待機」に「山札・疲労・連携」が乗る。→ D1〜D2 で連携カードを入れない。ヒント機能(任意)を手札対応させる。初見は「作戦パネルの予想」に頼れる。
- **バランスの崩れ**: カード報酬で強い組み合わせが生まれ得る。→ Botで「強いデッキ/弱いデッキ」の踏破率を比較し、疲労値で調整。
- **実装量**: BattleScene の手札UIとBotの全面改修が必要。→ 互換モード(D0)を残して段階的に移行。
- **スマホの操作性**: 手札数の増加。→ D1 で実機検証、上限3への縮小も選択肢。
